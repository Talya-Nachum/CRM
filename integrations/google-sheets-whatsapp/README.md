# אינטגרציית Google Sheets ↔ InforU WhatsApp ↔ NLPearl (שיחות קוליות)

## מבנה הגיליון

עמודות מזוהות לפי כותרת (שורה 1), לא לפי מיקום קבוע. חובה שיהיו כותרות בשמות האלה (בכל סדר עמודות):

**WhatsApp (InforU):**
- `טלפון נייד` — מספר הטלפון של איש הקשר
- `שם פרטי` — משמש למילוי התבנית (TemplateParameters) וגם ל-NLPearl (callData)
- `מספר תבנית` — מזהה תבנית WhatsApp לשורה הזו (אופציונלי, ברירת מחדל 267627)
- `סטטוס` — הקוד כותב לתוכה "נשלח וואטסאפ" אחרי שליחה מוצלחת
- `תשובת לקוח` — הקוד כותב לתוכה את תשובת הלקוח כשמגיעה
- `תאריך תשובה` — הקוד כותב לתוכה את מועד קבלת התשובה

**שיחות קוליות (NLPearl):**
- `מזהה קמפיין` — outboundId של הסוכנת/הקמפיין הרלוונטי לשורה (אופציונלי, ברירת מחדל מוגדרת בקוד)
- `סטטוס שיחה` — הקוד כותב "שיחה נשלחה" אחרי שהשיחה הותחלה בהצלחה
- `מזהה ליד NLPearl` — נשמר אוטומטית מהתגובה, משמש לזיהוי השורה כשמגיע Webhook
- `תוצאת שיחה` — הקוד כותב לתוכה את המידע שנאסף בשיחה (collectedData)
- `תאריך שיחה` — מועד קבלת עדכון השיחה

עמודת הטלפון צריכה להיות מעוצבת כטקסט (לא מספר), כדי לא לאבד אפס מוביל.

## התקנה

1. בגיליון: **תוספים (Extensions) → Apps Script**
2. להדביק את התוכן של `Code.gs` בעורך שנפתח
3. **Project Settings (גלגל השיניים) → Script Properties → Add script property**, ולהוסיף:
   - `INFORU_USERNAME` / `INFORU_TOKEN` — פרטי אינפוריו
   - `NLPEARL_ACCOUNT_ID` / `NLPEARL_SECRET_KEY` — מ-platform.nlpearl.ai/app/settings/api
4. `DEFAULT_TEMPLATE_ID` ו-`DEFAULT_OUTBOUND_ID` בקוד כבר מוגדרים לערכים הנוכחיים
5. להריץ `sendMessages` (WhatsApp) ו/או `startCalls` (שיחות) כדי לעבד שורות חדשות
6. אפשר לחבר טריגר זמן (Triggers ← Add Trigger) כדי שהפונקציות ירוצו אוטומטית

## הוספת לקוחות/קמפיינים חדשים

לא צריך לכתוב קוד חדש ולא לפרוס מחדש. פשוט מוסיפים שורות חדשות (או טאב חדש עם אותה מבנה עמודות) לאותו גיליון:
- תבנית WhatsApp אחרת? למלא ערך שונה בעמודת `מספר תבנית`.
- סוכנת NLPearl אחרת? למלא ערך שונה בעמודת `מזהה קמפיין`.

## קבלת עדכונים (Webhook משותף)

אותה כתובת Webhook אחת (מהפריסה) משרתת גם את InforU וגם את NLPearl — `doPost` מזהה את המקור לפי צורת ה-JSON:
- InforU: `{ "Data": [ { "Value": "<phone>", "Message": "<reply>" } ] }` → מתאים לפי טלפון, כותב ל-`תשובת לקוח`
- NLPearl: אובייקט עם `pearlId` בשורש (Lead Webhook או Call Webhook) → מתאים לפי `מזהה ליד NLPearl` (שנשמר בזמן `startCalls`), כותב ל-`תוצאת שיחה`

כל קריאה נכנסת (משני המקורות) נרשמת גם גולמית בטאב `WebhookLog` (נוצר אוטומטית) לצורך דיבוג.

כדי להפעיל בפועל:
1. **Deploy → Manage deployments → ערוך (עיפרון)**
2. לוודא: **Execute as: Me** (לא "המשתמש שנכנס לאפליקציה"), **Who has access: Anyone** (לא "Anyone with Google account" — לשרתים חיצוניים אין חשבון גוגל)
3. את הכתובת (URL, מסתיימת ב-`/exec`) לשלוח גם לאינפוריו וגם ל-NLPearl (אצל NLPearl: הגדרות הסוכנת → Overview → Webhooks → On, גם ל-Lead Webhook וגם ל-Call Webhook)

## הערת אבטחה

כל פרטי ההתחברות (Username/Token/AccountId/SecretKey) נשמרים רק ב-Script Properties (מוצפן, פרטי לגיליון) — לא כתובים בקוד עצמו.

## הערה על NLPearl

מבנה הבקשה ל-`Make Call` (endpoint, שמות שדות מדויקים) שוחזר מה-Python wrapper של NLPearl ומצ'אט התיעוד שלהם, ולא אומת מול תיעוד HTTP גולמי רשמי - יש לבדוק בפועל עם שיחת בדיקה אחת לפני שימוש בקנה מידה רחב, ולתקן אם יש פערים.

## כתובת Webhook יציבה (StableRelay.gs)

בעיה חוזרת: כל עריכת קוד ב-`Code.gs` שדורשת פריסה (Deploy) מחדש עלולה בטעות ליצור **פריסה חדשה** עם כתובת URL שונה (במקום גרסה חדשה לאותה פריסה) - מה שדורש לעדכן את הכתובת מחדש אצל InforU ו-NLPearl בכל פעם.

הפתרון: `StableRelay.gs` נפרס כפרויקט Apps Script **נפרד ועצמאי** (לא קשור לגיליון), שהכתובת שלו לעולם לא משתנה כי אין נוגעים בפריסה שלו יותר אחרי הפעם הראשונה. הוא רק מעביר הלאה כל בקשה שמגיעה אליו לכתובת ה"אמיתית" הנוכחית, שנשמרת ב-Script Property בשם `TARGET_URL`.

- InforU ו-NLPearl מקבלים את כתובת ה-**StableRelay** בלבד, פעם אחת, לתמיד.
- אם כתובת ה-`Code.gs` האמיתית משתנה בעתיד (כמו שקרה כמה פעמים) - מעדכנים רק את `TARGET_URL` ב-Script Properties של ה-Relay (בלי לפרוס מחדש, בלי לעדכן אף אחד בחוץ).
