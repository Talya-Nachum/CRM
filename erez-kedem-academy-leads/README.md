# ניהול לידים – ארז קדם אקדמיה

גיליון Google Sheets נפרד + Apps Script Web App לניהול הלידים של ארז קדם אקדמיה: קליטה אוטומטית מדף הנחיתה (כשתיסגר הפלטפורמה), הוספה ידנית, סטטוס לכל רשומה, ושליחת וואטסאפ מרובה-נמענים דרך אינפוריו (אותו API כמו במערכת הראשית).

## התקנה

1. **גיליון Google Sheets חדש** (ריק, לא הגיליון הראשי הקיים).
2. **תוספים (Extensions) → Apps Script**.
3. למחוק את `Code.gs` שנוצר אוטומטית, וליצור/להדביק את חמשת הקבצים מהתיקייה הזו:
   `Code.gs`, `Index.html`, `Stylesheet.html`, `JavaScript.html`, `appsscript.json` (את ה-manifest רואים דרך **Project Settings → Show "appsscript.json"**).
4. **Project Settings (גלגל השיניים) → Script Properties**, להוסיף:
   - `INFORU_USERNAME` — **להעתיק את אותו ערך** מה-Script Properties של הפרויקט הראשי (המערכת הקיימת שבה שולחים היום וואטסאפ ללקוחות אחרים).
   - `INFORU_TOKEN` — אותו דבר, להעתיק מהפרויקט הראשי.
   - `WEBHOOK_TOKEN` — אופציונלי. אם מוגדר, כל בקשת Webhook מדף הנחיתה תצטרך לשלוח `token` תואם, כדי שגורם חיצוני לא יוכל להזין לידים מזויפים. אפשר להשאיר ריק בינתיים.
5. **Deploy → New deployment → Web app**:
   - Execute as: **Me**
   - Who has access: **Anyone**
   - **Deploy**, ולהעתיק את כתובת ה-`/exec`. זו הכתובת שתשתמשי בה גם את/צוות ארז לניהול הלידים, וגם (בעתיד) דף הנחיתה כ-Webhook.
6. לפתוח את הכתובת בדפדפן — הגיליון ("לידים", "רשימת סטטוסים", "תבניות") ייווצר וייזרע אוטומטית בפעם הראשונה.

## מה לערוך לפני שמראים ללקוח

- **`ACADEMY_START_DATE`** בראש `Code.gs` — התאריך שהשעון סופר אליו לאחור. כרגע `1.10.26`, לעדכן לפי הצורך (פורמט ISO, למשל `'2026-10-01T00:00:00+03:00'`).
- **`PAYMENT_URL`** ו-**`INFO_URL`** באותו מקום — הכפתורים כבר בנויים בדשבורד, פשוט ריקים כרגע. ברגע שיש לינק אמיתי, למלא כאן ולפרוס גרסה חדשה (Deploy → Manage deployments → עיפרון → New version).
- **טאב "תבניות"** בגיליון — יש 3 שורות לדוגמה עם "מספר תבנית" = `להשלים`. להחליף במספרי התבנית האמיתיים מאינפוריו (אפשר גם לשנות שמות/למחוק/להוסיף שורות בלי לגעת בקוד).
- **לוגו** — כרגע placeholder (אייקון + טקסט "KEDEM") בתוך `Index.html`. כששולחים קובץ לוגו אמיתי, מחליפים את בלוק ה-`<svg>` בתגית `<img>` שמצביעה על הקובץ (או Base64 מוטמע).

## ניהול סטטוסים

הרשימה הסגורה של סטטוסים נמצאת בטאב **"רשימת סטטוסים"** (עמודה A). זו ההרשאה היחידה — מי שיש לו גישת עריכה לגיליון עצמו (כרגע: רק בעלת המערכת) יכול להוסיף/להסיר סטטוס. אין כפתור "הוספת סטטוס" בדשבורד בכוונה — כל מי שפותח את קישור ה-Web App רואה ומשתמש בסטטוסים הקיימים בלבד.

ברירת המחדל שנזרעת אוטומטית: חדש, בתהליך, נרשם לבד, נרשם ע"י מיטוב, בטיפול ארז, לא מעוניין.

## שליחת וואטסאפ

בטבלת הלידים בדשבורד יש checkbox על כל שורה. אחרי בחירת לידים, כפתור **"שליחת וואטסאפ"** נפתח, מציג את רשימת התבניות מהטאב "תבניות", ושולח קריאה אחת לאינפוריו (`capi.inforu.co.il`) עם כל הנבחרים כ-Recipients. אחרי שליחה מוצלחת נרשם תאריך בעמודת "וואטסאפ נשלח לאחרון" בטאב "לידים".

## חיבור דף הנחיתה (Webhook) — כשתיסגר הפלטפורמה

כתובת ה-`/exec` מקבלת POST עם JSON (מומלץ) או form-urlencoded. השדות מזוהים באופן גמיש (עברית/אנגלית) — לדוגמה:

```json
{
  "שם מלא": "ישראל ישראלי",
  "טלפון": "0501234567",
  "אימייל": "israel@example.com",
  "מקור": "פייסבוק"
}
```

או באנגלית: `{"full_name": "...", "phone": "...", "email": "...", "source": "..."}`.

שדות שלא סופקו (למשל שם חברה/ח.פ/תפקיד) נשארים ריקים ומשלימים ידנית מהדשבורד. סטטוס חדש תמיד מקבל את הערך הראשון ברשימת הסטטוסים ("חדש" כברירת מחדל). כל בקשה נכנסת נרשמת גם בטאב "WebhookLog" לצורך דיבוג.

## הערת אבטחה

פרטי ההתחברות לאינפוריו (`INFORU_USERNAME`/`INFORU_TOKEN`) נשמרים רק ב-Script Properties (פרטי לפרויקט) — אף פעם לא בקוד עצמו. הדשבורד עצמו לא חושף אותם ללקוח (הם נקראים רק בצד השרת, ב-`sendWhatsApp`).
